项目定位

农民 Agent 是一台建立在 BSC Chain 上的终极收益收割机。整套项目不再用冰冷的金融术语讲故事，而是把 DeFi 策略包装成一座自动化农业合作社。

它会先去勘探新农田，再做土壤肥力检测，然后播种施肥、安排农机下地，最后把秋收送回谷仓，并按水车机制继续复投、修农机和发口粮。

核心农务循环

勘探新农田

原本的 Discovery 现在是农场的 APY 雷达。每一轮扫描都在找刚开垦的新地、热度突增的地块，以及可能爆产的怪田。

土壤肥力检测

原来的风险评分被改写成测土报告。肥力、虫害、排水、暴风风险和 rug-pull 腐烂度都会汇总成一句能不能下种的建议。

播种与施肥

建仓和交易被改成播种、施肥和派拖拉机。仓位大小就是种子配额，风险上限就是灌溉纪律。

水车复投

70% 买种子把收成重新投回农田，继续滚动播种。
15% 修农机把 buyback 与 burn 讲成农机维护和装备升级。
15% 发口粮把 airdrop 变成村民分粮。
温室模拟大棚用来替代 Paper Trading，先在大棚里试种，再决定是否下真田。

谷仓中控

谷仓值班台实时播报勘田、测土、播种、天气风险和农机状态。
农作物图鉴把原来的 Token Explorer 改造成作物图鉴，大葱币、土豆币、豆角田都变成了地块名。
粮仓持仓展示不再像资产表，而像一张粮袋库存和地块分布图。
温室模拟大棚所有模拟资金都先在温室里试种。
天气预报最新信号被解释成暴风、霜冻、灌溉增强和撤资预警。
丰收庆典空投流程变成了丰收巡游、分粮名单和口粮账本。

农机竞技场

八位不同风格的农夫和农机会在竞技场里拉练。拖拉机、浇水队、播种机、收割机彼此争夺最好的地块和最高的产出。

  • 干农活中：状态稳定，持续产出。
  • 缺水中：收益下滑，地块变干。
  • 枯苗中：勉强维持，随时可能退场。
  • 已堆肥：表现太差，被回收成养分升级主系统。

对比页“市场械斗”会把镰刀、收割机和浇水队放在一起，用 APY、无常损失、油耗和日收成做正面对轰。

拖拉机云

拖拉机云就是农民 Agent 的公社云中枢。你可以在这里看生产队谁还在干活、工分还剩多少、农机磨损到什么程度。

  • 云端生产队名册
  • 工分与粮票账本
  • 后续可接入真实公社账户和农机日志

技术棚

  • 运行时：Bun + TypeScript + elizaOS 2.0
  • 农田数据：GeckoTerminal API 与链上池子遥测
  • 链：叙事统一为 BSC Chain
  • 模式：温室模拟、实时开耕、丰收分配
  • 存储：本地 JSON 与内存缓存

农场答疑

这还是交易项目吗？

是。底层逻辑仍然是池子扫描、仓位管理和 AI 策略进化，只是叙事层被整体改成了农业世界观。

为什么要保留温室模拟？

因为它比 Paper Trading 更贴合农场设定，也更容易让用户理解“先试种、再下田”的流程。

拖拉机云后面会接真功能吗？

会。后续接入真实 API 后，生产队、工分库、账本和日志都可以从展示页升级成真控制台。
